# Séance 1 : Expression du besoin 
Les étudiants sont répartis en groupes de 2. Dans un premier temps, ils jouent le rôle de clients et décrivent le besoin de leur application. Dans un second temps, ils jouent le rôle d'implantateurs API et reçoivent les besoins d'un autre groupe. 
Ils devront alors rédiger un cahier des charges fonctionnel et technique.

## Objectifs
- Comprendre l'importance de l'expression du besoin

### Description des livrables
I. Analyse du besoin 
    A. Contexte
        La description du contexte doit permettre de comprendre le projet dans son ensemble. Elle doit décrire le domaine d'activité, les enjeux, les contraintes, etc.
    B. Objectifs
        Les objectifs du projet doivent être clairement définis. Ils doivent être mesurables et atteignables. Exemple : "Le projet doit permettre de gérer les stocks de l'entreprise."
    C. Périmètre
        Le périmètre du projet doit être défini. Il doit permettre de savoir ce qui est inclus dans le projet et ce qui ne l'est pas.
    D. Contraintes
        Les contraintes du projet doivent être identifiées. Elles peuvent être de différentes natures : techniques, financières, temporelles, etc.
    E. Acteurs
        Les acteurs du projet doivent être identifiés. Il peut s'agir de personnes ou de systèmes informatiques.
    F. Exigences fonctionnelles
        Les exigences fonctionnelles du projet doivent être identifiées. Elles doivent décrire les fonctionnalités attendues du projet.
        Exemple : 
        - "Le projet doit permettre de gérer les stocks de l'entreprise."
        - "Le projet doit permettre de générer des rapports de suivi."
    G. Exigences non fonctionnelles
        Les exigences non fonctionnelles du projet doivent être identifiées. Elles doivent décrire les contraintes de qualité, de performance, de sécurité, etc. Exemple : "Le projet doit être sécurisé."
    H. Glossaire

II. Solution fonctionnelle proposée 
    A. Description générale
        La description générale de la solution doit permettre de comprendre comment elle répond aux besoins exprimés dans l'analyse du besoin.
    B. Fonctionnalités
        Les fonctionnalités de la solution doivent être décrites en détail. Elles doivent permettre de savoir ce que la solution permet de faire.
    C. Interfaces
        Les interfaces de la solution doivent être décrites. Elles doivent permettre de savoir comment les utilisateurs interagissent avec la solution.
    D. Exigences de performance
        Les exigences de performance de la solution doivent être identifiées. Elles doivent permettre de savoir comment la solution doit se comporter en termes de temps de réponse, de capacité, etc.
    E. Exigences de sécurité
        Les exigences de sécurité de la solution doivent être identifiées. Elles doivent permettre de savoir comment la solution doit protéger les données et les utilisateurs.
    F. Exigences de qualité
        Les exigences de qualité de la solution doivent être identifiées. Elles doivent permettre de savoir comment la solution doit être testée et validée.
    G. Glossaire
